# Privacy and source-verification boundaries

Recordings, transcripts, customer-derived facts, analyses, reviews and media access are confidential/test-only. Keep them out of Git, public buckets/assets, analytics, browser localStorage, ordinary logs and unsanitized screenshots/video. Only protected application storage holds customer content. Workflow arguments/returns are IDs and safe metadata, not audio, prompts, transcripts, responses or signed URLs.

Invite-only users obtain authorization from protected workspace membership, never editable user metadata. The owner can upload, initiate billable processing and delete. Reviewers can inspect prepared content and audit source/checkpoint evidence; they cannot trigger re-analysis. Raw source playback is not exposed. Short-lived playback uses the private prepared-media bucket; settled failed calls require valid checksum-bound preparation before that access supports source review.

Upload preparation records the authenticated owner's claim, admitted checksum, source kind and server time. It does not prove PII detection, redaction or that media really is fictional. Copying that recording into the sanitized bucket does not itself redact audio. The current scanner only holds obvious sensitive passages and is not comprehensive automatic sanitization. CALL-013 stays quarantined until its entire payment exchange is privately redacted and verified before provider upload or ordinary playback.

Source review changes speaker roles and attestations only. It cannot edit words, IDs, timestamps, rep/direction/call time, source paths, scores or raw model results. Original ASR and model snapshots remain protected and immutable; legacy snapshots are explicitly labelled legacy, not original ASR. Samples attest only fictional displayed text and never pretend someone listened to nonexistent fixture audio. Unknown/mixed speakers and unresolved quality/completeness remain visible. Verification is human source context, not an order to award passes or a guarantee that the model's semantic interpretation is right.

The exposed server key must be replaced before any further hosted use. Groq ZDR/no-training and current feature-specific retention exceptions must be verified on the account before real data. No training/data-sharing/fine-tuning/batch retention was enabled here. All current local/injected test data is explicitly fictional; no real recording or private transcript was imported in this slice.

Deletion tombstones stop ordinary access and stale writes. Owner cleanup inventories/removes registered and alternative owned copies before row/receipt success; incomplete cleanup stays retryable. Local and mocked tests do not certify hosted in-flight races, signed-link/cache invalidation, workflow/provider logs or backup destruction. Actual end-of-test deletion includes source/derivative/transcript/model/review/local-context copies and verified retention handling, after the test is complete. Keep receipts content-free.
