# Architecture and current boundaries

With Supabase connected, fictional recordings can upload without an AI key. Finalize checks the private object and checksum, persists `AI_NOT_CONFIGURED`, and does not dispatch the provider workflow. The UI shows Awaiting AI and an inactive Resume action until credentials exist. Real recordings remain gated separately. The recording-type field is an owner attestation, not an automated proof that media is fictional. Hosted Auth, direct upload, keyless admission, access denial and current-copy deletion were verified with generated silence on the dedicated project on 8 October 2026. No real recordings were uploaded; deployed-app/workflow/provider/backup-retention acceptance remains pending.

Next.js 16 App Router serves the interface and authenticated APIs. Supabase provides the production Auth, Postgres and private Storage boundary. Groq handles timestamped transcription and structured analysis. Vercel Workflow orchestrates stages with identifiers as input and output. Models, prompts, audio, transcript and analysis content are not workflow return values.

The user requested a keyless implementation phase. With no Supabase credentials, `npm run dev` exposes an explicitly fictional sample workspace. Its HMAC-signed, HTTP-only, same-site session lasts one hour. This route is unavailable in production and when Supabase is configured. Its file repository accepts `mode: sample` only and persists under ignored `.private/app`. This single-process development store is not the production database and must never hold client recordings. There is no filesystem persistence assumption on Vercel.

The normal app uses server-verified Supabase users and protected workspace memberships. Anonymous users and users without membership are rejected. The server repository checks workspace scope on every operation. The publishable client has read-only, membership-scoped database policies. Memberships, jobs and all database writes are administered through the protected server. The schema uses security-invoker functions, version comparison, advisory locks, original assessment preservation and deletion tombstones. No user-editable identity metadata grants a role.

Uploads go directly from an authenticated browser to private Storage. The server receives metadata only, checks the uploaded content signature and checksum at finalize, and starts an ID-only workflow. The current ceiling is 25 MB and 60 minutes. Oversize files/transcripts are rejected; there is no silent truncation. Actual server codec validation, chunk merging and resumable large-file uploads remain release work. Client decode checks are useful UX, not an authoritative duration check; Groq's returned duration is checked too.

Source upload policy requires an owner, a live call row and no deletion tombstone. Raw source objects have no client read policy. Playback returns a 60-second signed link to the separate sanitized bucket only after processing. Real recordings require private manual redaction before upload and explicit retention/privacy enablement. The current scanner holds obvious payment/identifier passages; it is not comprehensive PII detection or automatic audio redaction. A known payment exchange such as CALL-013 must be fully redacted and reviewed locally first. This phase imported no real audio.

The local remediation adds an unapplied additive migration binding owner uploads to the exact registered `sourcePath`, live mode, queued state and `UPLOAD_PENDING`. Both earlier migrations remain unchanged. Deletion now inventories source and derivative buckets with stable pagination, removes registered and alternative call-ID-prefixed copies, and verifies the inventory is empty before the row/receipt RPC. Any SDK error, surviving object or matching nested folder leaves a tombstoned call available for retry. This does not certify hosted in-flight upload races or backups. Copying a privately prepared recording to the sanitized bucket is not automatic audio redaction.

Analysis uses strict Zod/JSON Schema, exact segment and quote validation, fixed manual rubrics and deterministic arithmetic. Provider final grades are never accepted. Inaudible research, ambiguous applicability and unknown employee attribution remain unresolved. Whisper does not supply verified diarization: actual mono transcripts initially use unknown speakers and may need manual review rather than automatic official grades.

Ordinary ASR always starts unverified, even with good quality metrics or plausible silence. An authenticated owner/reviewer source endpoint accepts per-segment roles and explicit recording-versus-transcript completeness/quality attestations with a reason. Text/IDs/timestamps are immutable; preparation must match the admitted checksum and protected prepared-media path. Legacy real calls without preparation and active/privacy-held/tombstoned calls cannot be verified. First ASR/source snapshots record provenance; first raw model and latest raw model stay separate from effective results/history. No model or generic request field can certify the source.

Source review increments source/version revisions, preserves unrelated model/applicability reasons and makes previous analysis stale. Owners initiate re-analysis through the durable claim boundary; stored segments skip ASR. The provider receives trusted source context, not an instruction to pass. Publication checks attempt/run, source revision and version, preserves first originals, updates latest raw output and ties effective analysis to that revision. Old manual decisions remain labelled history. Empty-key refusal happens before mutation/dispatch and never produces a fixture replacement. Checkpoint review is blocked while stale/active and requires exact selected employee evidence and reliable verified source for passes/misses. Model uncertainty and fixed denominators still govern grade. This is not automated diarization/redaction or a semantic-accuracy guarantee.

Actual local sample testing now uses fresh UUID roots under ignored `.private/qa/` for both datastore and HMAC key, separate build output and loopback port 3002. A repeatable presenter launcher uses `.private/demo/` and port 3003. Overrides empty all backend/provider credentials and keep real processing false, without editing `.env.local`. Ordinary `.private/app/` is untouched. The root is server-selected, path-boundary checked and never accepted from HTTP. Production/configured-backend sample enablement is unchanged. Actual local APIs, API-intercepted port-3001 UI, injected provider ports and hosted recording acceptance remain distinct evidence categories.

Review decisions require a reason and the reviewed version. Original and effective assessments are distinct; one correction cannot clear unrelated questions. Deletion tombstones precede object/row deletion, and database late saves fail. Object-storage cleanup races, durable workflow recovery, token revocation and external backup/log retention still require actual Supabase/Vercel verification. Local SQL tests do not establish those hosted guarantees.

Retry and validated upload-finalize dispatch persist a server-owned pending attempt identifier before starting a workflow. Pending retries reuse that identifier, even when a failed-start recovery read/write is unavailable. Successful dispatch needs no further route-side database write; a worker must claim the attempt with a versioned compare-and-set using its SDK workflow run ID before provider effects. Duplicate starts can create idle runs, but only one run may own an attempt. Entry, pre-provider, pre-derivative and pre-publication checks reject deleted or superseded work; legacy runs cannot take tracked attempts. Terminal success, privacy hold and terminal failure finish the same owner within the result write; temporary failures preserve the running owner for step retry. Running or untracked active calls cannot be arbitrarily restarted, and stale-running-job reconciliation remains pending. All workflow arguments/returns stay identifiers and safe metadata. These are locally simulated contracts, not hosted queue/recovery acceptance.

Owner Data controls obtains a workspace-scoped count-only retention summary, including retained tombstoned rows. Bulk deletion includes those rows so failed media cleanup can be retried; ordinary call listing, detail and playback still hide them. Summary loading/failure never masquerades as zero, and reviewer counts are explicitly available conversations. Counts are refreshed observations rather than atomic certifications of concurrent deletion; bucket verification still precedes the row/receipt RPC.

UI components use native accessible controls/dialogs with custom Tailwind/CSS styling and Lucide icons. The implementation uses normal Next routing and bounded polling, without introducing a state library for this V1. This is an intentional simplification of the original shadcn/TanStack proposal. No external fonts, analytics or transcript localStorage are used.
