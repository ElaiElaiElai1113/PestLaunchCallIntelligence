# Architecture and current boundaries

With Supabase connected, fictional recordings can upload without an AI key. Finalize checks the private object and checksum, persists `AI_NOT_CONFIGURED`, and does not dispatch the provider workflow. The UI shows Awaiting AI and an inactive Resume action until credentials exist. Real recordings remain gated separately. The recording-type field is an owner attestation, not an automated proof that media is fictional. Hosted Auth, direct upload, keyless admission, access denial and current-copy deletion were verified with generated silence on the dedicated project on 8 October 2026. No real recordings were uploaded; deployed-app/workflow/provider/backup-retention acceptance remains pending.

Next.js 16 App Router serves the interface and authenticated APIs. Supabase provides the production Auth, Postgres and private Storage boundary. Groq handles timestamped transcription and structured analysis. Vercel Workflow orchestrates stages with identifiers as input and output. Models, prompts, audio, transcript and analysis content are not workflow return values.

Current 9 October authority permits direct fictional Groq probes with the server-only test key; historical keyless-hosted evidence above is unchanged. Ordinary sample harnesses force empty keys and real customer processing remains disabled. Analysis admission uses a 12,000-byte messages/schema heuristic, a 3,000-token output cap and low reasoning without returned reasoning. Budget failure is terminal, retains source/history and displays a truthful limit notice. No chunking, quota upgrade or whole-60-minute analysis guarantee was added. Raw/normalized provenance publishes only under the existing attempt/run/version/source-revision CAS; workflow returns remain IDs. The dedicated hosted server-key/migration/access and deployed acceptance gates remain open.

The user requested a keyless implementation phase. With no Supabase credentials, `npm run dev` exposes an explicitly fictional sample workspace. Its HMAC-signed, HTTP-only, same-site session lasts one hour. This route is unavailable in production and when Supabase is configured. Its file repository accepts `mode: sample` only and persists under ignored `.private/app`. This single-process development store is not the production database and must never hold client recordings. There is no filesystem persistence assumption on Vercel.

The normal app uses server-verified Supabase users and protected workspace memberships. Anonymous users and users without membership are rejected. The server repository checks workspace scope on every operation. The publishable client has read-only, membership-scoped database policies. Memberships, jobs and all database writes are administered through the protected server. The schema uses security-invoker functions, version comparison, advisory locks, original assessment preservation and deletion tombstones. No user-editable identity metadata grants a role.

Uploads go directly from an authenticated browser to private Storage. The server receives metadata only, checks the uploaded content signature and checksum at finalize, and starts an ID-only workflow. The current ceiling is 25 MB and 60 minutes. Oversize files/transcripts are rejected; there is no silent truncation. Actual server codec validation, chunk merging and resumable large-file uploads remain release work. Client decode checks are useful UX, not an authoritative duration check; Groq's returned duration is checked too.

Source upload policy requires an owner, a live call row and no deletion tombstone. Raw source objects have no client read policy. Playback returns a 60-second signed link to the separate sanitized bucket only after processing. Real recordings require private manual redaction before upload and explicit retention/privacy enablement. The current scanner holds obvious payment/identifier passages; it is not comprehensive PII detection or automatic audio redaction. A known payment exchange such as CALL-013 must be fully redacted and reviewed locally first. This phase imported no real audio.

The local remediation adds an unapplied additive migration binding owner uploads to the exact registered `sourcePath`, live mode, queued state and `UPLOAD_PENDING`. Both earlier migrations remain unchanged. Deletion now inventories source and derivative buckets with stable pagination, removes registered and alternative call-ID-prefixed copies, and verifies the inventory is empty before the row/receipt RPC. Any SDK error, surviving object or matching nested folder leaves a tombstoned call available for retry. This does not certify hosted in-flight upload races or backups. Copying a privately prepared recording to the sanitized bucket is not automatic audio redaction.

Analysis uses strict `call_analysis_refs_v1` Zod/JSON Schema. The model selects ordered segment references; deterministic materialization displays exact full source excerpts and attaches coaching to its parent checkpoint. Empty/duplicate source IDs, unknown/duplicate/out-of-order references, overlong excerpts, wrong rubric membership and extra legacy quote fields are rejected. Exact raw JSON is preserved in protected first/latest provider provenance, separately from normalized original/latest/effective assessments; legacy originals are not relabelled. Existing evidence/role/quality/completeness guards, fixed manual rubrics and deterministic arithmetic remain mandatory. A structurally valid reference can still be semantically irrelevant. Provider final grades are never accepted. Inaudible research, ambiguous applicability and unknown employee attribution remain unresolved. Whisper does not supply verified diarization: actual mono transcripts initially use unknown speakers and may need manual review rather than automatic official grades.

Ordinary ASR always starts unverified, even with good quality metrics or plausible silence. An authenticated owner/reviewer source endpoint accepts per-segment roles and explicit recording-versus-transcript completeness/quality attestations with a reason. Text/IDs/timestamps are immutable; preparation must match the admitted checksum and protected prepared-media path. Legacy real calls without preparation and active/privacy-held/tombstoned calls cannot be verified. First ASR/source snapshots record provenance; normalized original/latest assessments and exact first/latest provider JSON stay separate from effective results/history. No model or generic request field can certify the source.

Source review increments source/version revisions, preserves unrelated model/applicability reasons and makes previous analysis stale. Owners initiate re-analysis through the durable claim boundary; stored segments skip ASR. The provider receives trusted source context, not an instruction to pass. Publication checks attempt/run, source revision and version, preserves first originals, updates latest raw output and ties effective analysis to that revision. Old manual decisions remain labelled history. Empty-key refusal happens before mutation/dispatch and never produces a fixture replacement. Checkpoint review is blocked while stale/active and requires exact selected employee evidence and reliable verified source for passes/misses. Model uncertainty and fixed denominators still govern grade. This is not automated diarization/redaction or a semantic-accuracy guarantee.

Local recovery controls now cover first-analysis failures with no previous result. Source review records the prior failure code without dispatching work. A pure current-request admission helper is shared by the client and the owner route; TextEncoder byte accounting is tested equivalent to UTF-8 Buffer accounting. Old budget failures do not permanently disable a now-admissible audited source, while an unchanged oversized request fails before dispatch. Eligible settled transcripts wait for an explicit owner action; protected-source/privacy/active/version/deletion boundaries still apply. Reviewer access does not grant initiation rights.

Probe acceptance is separate instrumentation: versioned mandatory fixture assertions detect business contradictions, unresolved outcomes, missing follow-up/coaching and non-reference-verified facts. They cannot certify arbitrary semantic relevance or usefulness. Full optional-probe admission additionally requires a complete manual audit covering purpose, outcomes, follow-ups, facts, checkpoints and coaching, tied to the exact source/result hashes and case. Legacy boolean markers are ignored. The failed current round is closed without changing its three entries or response artifacts; no probe/CLI execution occurred in this local control repair.

Provider-input admission is now factored independently of review/run-state exclusions. Both transcript Retry and Analyze/Re-analyze require prepared source, privacy permission and the current unchanged budget. Pending-start retry keeps ownership intent; current-result status restoration skips new provider input, while initial audio resume keeps the existing upload/transcription path. Running/untracked work and CAS/tombstones remain controlled separately. Probe audit v3 separates hard required checks from content/evidence-identical display-label notes; only complete source/result-bound manual review can resolve label semantics. Changed facts/evidence or business contradictions remain hard blockers, and automatic fixture-label agreement is not a client requirement.

Actual local sample testing now uses fresh UUID roots under ignored `.private/qa/` for both datastore and HMAC key, separate build output and loopback port 3002. A repeatable presenter launcher uses `.private/demo/` and port 3003. Overrides empty all backend/provider credentials and keep real processing false, without editing `.env.local`. Ordinary `.private/app/` is untouched. The root is server-selected, path-boundary checked and never accepted from HTTP. Production/configured-backend sample enablement is unchanged. Actual local APIs, API-intercepted port-3001 UI, injected provider ports and hosted recording acceptance remain distinct evidence categories.

Review decisions require a reason and the reviewed version. Original and effective assessments are distinct; one correction cannot clear unrelated questions. Deletion tombstones precede object/row deletion, and database late saves fail. Object-storage cleanup races, durable workflow recovery, token revocation and external backup/log retention still require actual Supabase/Vercel verification. Local SQL tests do not establish those hosted guarantees.

Retry and validated upload-finalize dispatch persist a server-owned pending attempt identifier before starting a workflow. Pending retries reuse that identifier, even when a failed-start recovery read/write is unavailable. Successful dispatch needs no further route-side database write; a worker must claim the attempt with a versioned compare-and-set using its SDK workflow run ID before provider effects. Duplicate starts can create idle runs, but only one run may own an attempt. Entry, pre-provider, pre-derivative and pre-publication checks reject deleted or superseded work; legacy runs cannot take tracked attempts. Terminal success, privacy hold and terminal failure finish the same owner within the result write; temporary failures preserve the running owner for step retry. Running or untracked active calls cannot be arbitrarily restarted, and stale-running-job reconciliation remains pending. All workflow arguments/returns stay identifiers and safe metadata. These are locally simulated contracts, not hosted queue/recovery acceptance.

Owner Data controls obtains a workspace-scoped count-only retention summary, including retained tombstoned rows. Bulk deletion includes those rows so failed media cleanup can be retried; ordinary call listing, detail and playback still hide them. Summary loading/failure never masquerades as zero, and reviewer counts are explicitly available conversations. Counts are refreshed observations rather than atomic certifications of concurrent deletion; bucket verification still precedes the row/receipt RPC.

UI components use native accessible controls/dialogs with custom Tailwind/CSS styling and Lucide icons. The implementation uses normal Next routing and bounded polling, without introducing a state library for this V1. This is an intentional simplification of the original shadcn/TanStack proposal. No external fonts, analytics or transcript localStorage are used.

# AI adapter renewal — 9 October

The current `call_analysis_staged_v2` adapter separates detail extraction from purpose-specific scoring. Scoring requires every exact rubric key and three nullable coaching slots (one strength/two improvements); each slot selects a required checkpoint and inherits its exact source evidence. Protected provenance stores both exact response strings. Public evidence/scoring/attribution checks remain, with a conservative lexical review trigger for unsupported coaching policy terms. That trigger is not a semantic or company-policy verifier.

The workflow rechecks ownership/version/source/privacy before cache writes, the second transmission and publication; superseded work exits without mutation. Each request has conservative admission. Validated extraction is protected in the call payload and bound to source/context, version, attempt/run, model/contract and request hash. Same-attempt quota retries resume scoring; publication clears the cache. Three retries are allowed; exhausted transient failures finish the owned attempt in a retryable failed state. No customer content enters durable step parameters or results.

The direct harness's quota pacing and offline cache tests do not prove deployed runtime recovery: the adapter issues stages immediately and actual hosted quota/concurrency/crash verification remains pending. No complete long-call support is claimed from short direct probes.

## Full-call request encoding — 9 October

The legacy short-source contract remains unchanged. Whole-case admission can use `call_analysis_index_refs_v1` for larger transcripts: the complete ordered dialogue is presented as role/text rows and evidence selects zero-based integer indices. Code decodes these against the unchanged original ID/timestamped source and applies all existing validators. Source-ID enums become equivalent integer ranges (or employee-only integer enums). There is no transcript trimming, segment merging, role inference or summary substitution. Raw response bytes, reference mapping and full source hash remain protected provenance. Compact extraction reuse binds the entire original segments, including timestamps, as well as the request.

If full-rubric scoring still exceeds admission, split only the checkpoint set into groups of up to six. Every group sees the whole dialogue and its own exact manual guidance. All groups must validate and agree on the no-objection claim before an accepted result can be published. Original rubric order and denominator are retained. Up to one strength and two improvements are displayed in checkpoint-group order; all raw group suggestions are preserved in provenance. This ordering is deterministic, not a claim of global model prioritization. Permission/source/version checks and quota pacing run before each group. No partial group result is published.

Limits remain 12,000 serialized request bytes and 8,000 conservative estimated tokens per request; compact output reserves are 2,000 for extraction, 2,600 for whole-rubric scoring and 1,700 per checkpoint group. This admits the observed 112-turn / 5,096-character source locally. Inputs above this range may still be refused; 60 minutes is the upload ceiling, not verified analysis acceptance. Live transport, model accuracy and hosted new-upload checks for the compact path are separate pending evidence.
